# hwigi-tower — Design Agenda

> **외부 LLM 디벨롭 큐**. 어떤 토픽을 다음에 디벨롭할지, 무엇을 묻고 결정해야 하는지의 우선순위 큐.
> 사용 흐름:
> 1. 본 파일에서 토픽 1개 선택
> 2. [[hwiglija-tower-design-brief]] **전체** + 본 파일의 **해당 토픽 프롬프트** 를 외부 LLM (Gemini 권장) 에 붙여넣기
> 3. 답변 받고 추가 질문으로 정제
> 4. 작가 확정 → Sub brain (Claude) 채팅에 "**확정: <토픽> — <결정 내용>**" 로 공유
> 5. Claude 가 GDD / tone-bible / design-journal 에 반영 + version bump

## 토픽 1 — NPC 외형·성별

### 작가가 결정해야 할 변수
- 성별 (남 / 여 / 무성·중성)
- 연령대 (20대 / 30대 / 40대+)
- 체형 (마름 / 평균 / 풍채)
- 색상 톤 (한기·푸른 계열 / 따뜻한 회색 / 흙색)
- 상징물 (모자·외투·짐보따리·검·지팡이 등 1-2개)
- 한국적 vs 무국적 vs 이국적 비주얼 비중
- *훼손의 단계적 시각화* — S3-S4 글리치를 외형 어디에 누적시킬 것인가 (모자 균열? 그림자 흩어짐? 색 빠짐?)

### 외부 LLM 에게 던질 프롬프트
```
[brief 첨부 후 본 블록 입력]

토픽: 마타이오스의 외형·성별 옵션 디벨롭 (GPT-5.5 Outcome-First 패턴 적용)

# Goal: 잃어버린 유대와 기억이라는 서사적 핵심에 부합하는 시각적 정체성 확립.
# Success Criteria: 
- D-017/D-019 와의 정합성.
- 21일 솔로 외주 마감 가능한 복잡도.
- 단계별(S0/S2/S4) 훼손의 시각적 누적 계획 포함.
...
```

## 토픽 2 — 능력 12 + 시너지 4 효과·수치

### 작가가 결정해야 할 변수
- 능력 12 각각의 효과·수치·쿨다운 (검 3 / 술 3 / 선 3 / 결 3)
- 시너지 발동 조건 (3장 모음 = 정확히 3장? 3장 이상?)
- 시너지 4 효과의 *체감 강도 비교* (광폭/연소/관통/반사 중 어느 것이 가장 강한가)
- 픽업 빈도 (1런 5-7 노드 중 능력 픽업 노드 몇 개?)
- 회차 누적 시 시작 능력 풀 확장 메커니즘 (D-009 메타 진행)

### 외부 LLM 에게 던질 프롬프트
```
[brief 첨부 후 본 블록 입력]

토픽: 능력 12 + 시너지 4 의 효과·수치 디자인

제약:
- 1런 5-7분 (P3) → 능력 1개의 효과는 즉시 체감 가능해야
- 결정성 (P4) → 효과는 시드 RNG 로 결정적
- 양적 다양성 거부 (Anti-Pillar) → 12개가 *충분히 깊다* 는 것을 효과 상호작용으로 증명
- 4 태그: 검(직접·근접) / 술(원소·광역) / 선(원거리·관통) / 결(방어·반격)

요청:
1. 능력 12개를 태그별 3개씩 제시 (이름·효과 1줄·핵심 수치·상호작용 1줄).
2. 시너지 4 (광폭/연소/관통/반사) 발동 조건 + 효과를 슬레이 더 스파이어급 *명료성* 으로 정의.
3. 픽업 노드 빈도 추천 (P3 호흡 고려).
4. 회차 누적 메타 확장의 가장 가벼운 형태 1개 제안 (스코프 폭발 방지).
5. 작가 결정 필요 항목 정리.
```

## 토픽 3 — on-device LLM 검증 기준

### 작가가 결정해야 할 변수 (Codex 기술 검증 *전*에)
- "한국어 자연도 합격" 의 구체 기준 (몇 % 의 발화가 어색하지 않으면 합격?)
- "지연 합격" 의 구체 기준 (모바일 추론 1.5s 가 정말 마지노선인가?)
- 어색한 한국어가 P2 (LLM 한계 = in-game 진실) 위에서 *오히려 자산*이 되는 단계 명시 (S3-S4 만 허용? S0-S2 도 일정 수준 허용?)
- fallback 발동 조건 (어떤 지표 하나라도 미달이면 클라우드?)

### 외부 LLM 에게 던질 프롬프트
```
[brief 첨부 후 본 블록 입력]

토픽: on-device LLM (HyperCLOVA X SEED 0.5B) 합격선 정의

맥락:
- 05-04 가 D-005 fallback 결정점
- Codex 가 W1-2 에 1차 통합하고 결과 보고 예정
- P2: LLM 한계는 in-game 진실 — S3-S4 에선 어색한 한국어가 오히려 자산

요청:
1. 측정 가능한 합격 기준 5개 정의 (예: "회상 발화 30개 샘플 중 24개 이상 자연"):
   - 한국어 자연도
   - 지연
   - 캐릭터 일관성 (페르소나 유지)
   - 한국적 톤 (브리프의 톤 §4)
   - 결정성 (같은 입력 → 같은 출력)
2. S0-S2 (회복기) vs S3-S4 (붕괴기) 의 합격 기준 *비대칭* 설계 (P2 활용).
3. fallback 발동 룰 (전부 통과면 on-device, 하나라도 미달이면? AND/OR?).
4. 작가 결정 필요 항목 정리.
```

## 토픽 4 — 메모리 파편 5개 텍스트

### 작가가 결정해야 할 변수
- 5개 파편이 5단계(S0-S4) 와 1:1 매핑되는가, 아니면 S2-S4 에 누적 노출되는가
- 각 파편의 시점·화자 (누구의 시점? 마타이오스 자신? 잃어버린 *그 사람*? 양가?)
- "회차 0 이전 유대" 의 암시 강도 (모호하게? 한 파편에선 명확하게?)
- 파편 5 (최종 노출) 가 S5 엔딩 선택에 *어떤 무게* 로 작용하는가

### 외부 LLM 에게 던질 프롬프트
```
[brief 첨부 후 본 블록 입력]

토픽: 메모리 파편 5개 텍스트 (음역 C — 시적·단편적·시점 흐림)

제약:
- D-019: 잃어버린 것 = 플레이어와의 유대 + 본인의 기억, 종착 = 재망각
- 음역 C: 누구의 기억인지 명시하지 않는다
- 금지선: NPC 가 자기 이름 의미(μάταιος "무가치") 를 직접 설명 X
- 파편 1 샘플 (canonical): "누군가의 손이 내 손을 잡았다. 따뜻했다. 누구였는지 기억나지 않는다."
- 파편 5 샘플 (canonical): "잊는 게 무서운 게 아니야. 잊었다는 사실조차 잊는 게 무서워."
- 파편 2-4 미작성

요청:
1. 파편 2-4 (S2 ~ S4 사이 노출) 의 텍스트 후보 각 2-3 개 제시.
2. 5개 파편이 누적될 때의 *서사 곡선* 점검 (회복 → 균열 → 붕괴 직전).
3. "회차 0 이전 유대" 암시를 어느 파편에 어떤 강도로 박을지 추천.
4. 모든 후보가 음역 C + 금지선 위배 없는지 명시.
```

## 토픽 5 — 안식 vs 동행 엔딩 메커니즘 차이

### 작가가 결정해야 할 변수
- 안식(A) 컷씬 길이 vs 동행(B) "다음 회차로 회귀" 처리
- 메타 영향: 엔딩 A 후 새 게임은 진짜 "끝"인가, 아니면 새 NPC 와 다시 시작?
- 엔딩 B 의 다음 회차에서 마타이오스는 S0 으로 *완전 리셋* 되는가, 아니면 미세한 *기시감 잔재* 가 남는가
- 엔딩 갤러리 (D-009 메타 진행) 표시 방식

### 외부 LLM 에게 던질 프롬프트
```
[brief 첨부 후 본 블록 입력]

토픽: 안식(A) / 동행(B) 엔딩 메커니즘 차이

제약:
- D-013: 안식 아이템 획득 후 플레이어 선택
- D-019: 둘 다 망각으로 수렴 — A 능동 / B 수동 루프
- P5: 선택은 결과를 미루지 않는다
- W3-1 (~05-14) 마감, 솔로 + 외주 컷씬 2개

요청:
1. A 와 B 의 메커니즘 차이를 *연출/구조/메타* 3축에서 옵션 3-4 개 제시.
   예: "A 는 풀 컷씬 30s + 게임 종료, B 는 5s 페이드 + 1층 재진입 + 마타이오스 미세 기시감 발화"
2. 각 옵션이 P1 (망각의 양가성) 을 어떻게 강화하는가 점검.
3. 외주 컷씬 작업량 비대칭 우려 점검 (한쪽에 자원 쏠리지 않는가).
4. 작가 결정 필요 항목 정리.
```

## 토픽 9 — NPC Reflection JSON 스키마 (Structured Outputs)

### 재사용 자산 (이미 학습된 prompt — 한국어 번역만 필요)
- [[zep-graphiti]] §14 — Entity Extraction / Resolution / Fact Extraction / Temporal Extraction 5종 prompt (논문 Appendix 6.1, 검증된 production 표준)
- 본 prompt 들이 한국어로 번역되면 reflection 파이프라인 LLM 호출 prompt 로 직접 사용 가능

### 작가가 결정해야 할 변수
- reflections 테이블 (D-006) 의 emotion_pad 좌표계 — Russell PAD (-1~+1) 그대로 vs 단순 valence/arousal 2축
- keywords 배열 길이 (3개? 5개?)
- summary 문장 수 (현재 D-006: 3문장)
- **포맷 파괴 방지**: AI 가 자유 텍스트를 뱉지 않도록 `reflections.emotion_pad` 스키마 강제 통제망 확립
- **★ Bi-temporal 도입 여부** ([[zep-graphiti]] §4) — reflections 에 (t_valid, t_invalid) 컬럼 추가? 마타이오스 S3-S4 망각을 *edge invalidation* 으로 표현 가능 (P2 위에서 narrative + 기술 동시 강화)

### 외부 LLM 에게 던질 프롬프트
```
[brief 첨부 후 본 블록 입력]

토픽: 회차 reflection 의 JSON 스키마 (D-006 SQLite reflections 테이블용) 및 Structured Outputs 통제

제약:
- 1런 = 5-7분, 회차당 1 reflection 생성 (LLM 호출 1회)
- **정확히 reflections.emotion_pad 스키마에 맞는 JSON만 출력**하도록 프롬프트 구성
- 결정성 (P4): 같은 입력 → 같은 출력, 캐시 가능해야

요청:
1. JSON Schema 정의 및 에이전트가 포맷을 파괴하지 않도록 강제하는 prompt 지침.
2. summary (string, 3문장), keywords (array, N개), emotion_pad ({p,a,d} float -1~+1) 필드 구성.
3. on-device 0.5B 모델이 schema 강제 출력에 실패할 경우를 대비한 유효성 검사 루직 제안.
4. 작가 결정 필요 항목 정리.
```

## 토픽 10 — on-device LLM Eval 설계

### Warp 환경에서의 정량적 평가 파이프라인
Warp 터미널과 Codex CLI를 결합하여 **On-device 모델 측정 자동화**를 수행합니다.

### 작가가 결정해야 할 변수
- Eval 데이터셋 크기 (회차별 발화 30개? 50개?)
- **합격선 정의**: "OQ-004 LLM Eval 설계"를 워크플로우 내에 구체화 (자연도, 지연, 일관성)
- 측정 차원 가중치 (어느 게 가장 무거운가)
- Eval 자동화 방식 (Codex 가 LLM-as-judge 로 채점? 작가 수동?)

### 외부 LLM 에게 던질 프롬프트
